## 3. 字体与数字

中文使用系统字体 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。这是对微信中文阅读和包体的选择；不下载大体积中文字体，不引入Google字体依赖。品牌标识保持原素材。

| 层级 | 375px设计基准 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | 28px | 600 | 1.3 |
| 分区标题 | 20px | 600 | 1.4 |
| 作品名称 | 18px | 600 | 1.4 |
| 正文/主按钮 | 16px | 400 / 600 | 1.5 |
| 说明 | 14px | 400 | 1.5 |
| 辅助标记 | 12px | 400 / 500 | 1.5 |
| 价格/资产数字 | 22px | 600 | 1.2 |

全局不使用900字重。美甲商品金额用简洁的“¥金额”，保留小数语义；未设置金额显示“到店定价”。不在商品卡重复参考价、时长、卸甲、确认事项等说明。中文段落左对齐，不加字间距。标题最长两行的视觉目标不等于强制截断；长名称换行，不能遮挡预约按钮。放大字体时容器自然增高。

实现时布局可用rpx，但正文和点击区必须有逻辑像素下限；375px基准1px=2rpx，不能把这个比例当成所有屏宽的物理尺寸。字体缩放读取能力及真机表现需实测，不仅靠rpx缩放。

## 4. 8pt间距与结构

- 主尺度：8 / 16 / 24 / 32 / 48 / 64px；4px仅用于图标文字、标签等微距。
- 页面左右24px基准（48rpx），320px窄屏16px；大型屏幕限制内容列最大560px并居中。
- 标题到描述8px；描述到分类24px；分类到作品16px；作品之间32px；大分区之间48px。
- 作品信息内边距16px；文字与动作间16px。按钮之间8px，尺寸不足时换行，不压缩命中区。
- 小屏日历有7列，左右边距可局部降为4px、列间距0，使320px宽下每格仍≥44px；高度48px，日期状态另用可读行/选日说明。
- 保留原生导航与四项tabBar；页内不重复添加自制返回栏。导航/内容主题一致；用户胶囊区域由微信管理。

## 5. 圆角、层级与组件语言

- small 8px：小标签与辅助控件；control 12px：按钮/输入；media 16px：照片；sheet 24px：弹层上角。胶囊仅用于分类，不能给所有元素同样999px圆角。
- 作品卡默认不加阴影，以照片、排版和间距分组。明确可操作的表面使用轻边界。底部弹层才使用 `0 -8px 32px rgba(24,29,35,.12)`；深色主要依赖表面差异。
- 按钮：主按钮深墨实底（深色主题为浅底）、次按钮边界/浅底、文字动作。主按钮48px高，宽度由文字和24px左右内边距确定，不设固定窄宽。
- 图标统一24px画布、约1.75px描边、圆端点。复用项目图标语义，确认线宽后统一资产；源文件可用SVG，原生tabBar使用适配的PNG输出，避免假设微信原生tab支持内联SVG。
- 小图标外侧点击区至少48px；收藏必须保留“收藏/已收藏”和选中状态，不用仅颜色的心形代替。主操作使用原生button语义，清理微信默认伪元素边框时保留明确状态。

建议呈现层组件：`ProductDetailContent`、`ProductActionBar`、`CatalogProductCard`、`CatalogState`、`UiButton`。优先组合现有 `ProductGallery`、`FavoriteButton`、`StoreContact`；不新增状态库，不迁移业务工具。组件传props并emit动作，数据请求、登录判断与预约意图继续由现有页面/工具持有。

共享组件新增可选 `appearance="gallery"`，默认旧版；防止试点页改动立即影响饰品、鲜花、收藏。批准后再逐页迁移，不把页面私有样式变成全局标签选择器。

首批覆盖美甲详情，后续复用到饰品和鲜花，保留“预约此款 / 预约预留 / 预约取花”的业务差异。详情结构、入口/返回、数据状态和动效表见 `INTERACTION.md`。

## 7. 状态与交互

| 状态 | 呈现和动作 | 保持的业务语义 |
| --- | --- | --- |
| 初次加载 | 固定照片比例的静态占位+“正在加载作品” | 不先显示空态/假商品 |
| 分类切换 | 选中分类有文字/填充变化，内容区域标记加载 | 保留请求版本保护，不让旧分类覆盖新结果 |
| 加载失败 | “作品暂未加载”+重新加载按钮 | 不表示无库存、不展示虚构成功 |
| 空目录 | “暂时没有上架作品，可先预约到店沟通” | 保留通用预约和联系门店能力 |
| 图片缺失 | 中性占位+“图片待补充” | 不用会员卡纹理充当作品照；现有回退机制改动需单独验证 |
| 收藏 | 按压反馈、已收藏文字、忙碌期间禁用 | 按账户本地保存；不自动提交预约 |
| 预约 | 操作状态可感知，随后进入现有身份/预约路径 | 登录和手机号流程完整保留；申请不等于确认 |
| 长标题/未知参考价 | 自然换行、现有价格提示文案 | 不伪造金额/时长/折扣 |

动效成为本轮明确设计内容，但每个效果都服务于状态理解。按压100ms、收藏反馈160ms、内容切换140ms、预约面板进入220ms/退出180ms，详情优先使用微信原生转场。实现细节和低性能降级见 `INTERACTION.md`；不要叠加原生页面转场与自制全屏动画。

减少动态模式使用0ms/静态状态；若当前微信环境无法可靠识别偏好，自动装饰动效关闭，保留静态状态和原生交互，不宣称已自动适配系统设置。不自动轮播、不做滚动视差或无限闪动骨架。

## 8. 主题、安全区与兼容

Token先定义两套主题，组件通过语义变量读取；不要直接把浅色图片反相。系统主题监听可参考 [uni.onThemeChange官方文档](https://uniapp.dcloud.net.cn/api/system/theme.html)，实际支持还要用当前uni编译器和微信基础库验证。

原生导航与tabBar颜色需要配套主题配置；不能只用CSS媒体查询完成整机适配。当前全局未启用darkmode，试点阶段先验证组件双主题，然后为其余页面建立兼容色映射并回归，才启用全局系统主题跟随。若尚未完成，明确交付为“深色方案已定义，系统跟随待验收”，不宣称全局支持完成。

保留原生导航管理顶部安全区，不重复加statusBar高度。底部弹层采用 `padding-bottom: calc(16px + env(safe-area-inset-bottom))`，考虑键盘和内容滚动；固定控件要同时保留安全区和自身高度。原生tabBar页不重复硬编码一层tab高度。

最低验收尺寸320、375、390、430px，另检验平板/横屏及大字。真机确认rpx、字号、导航胶囊和底部区域；浏览器示意不能代替微信。

## 9. 实施顺序（视觉方向确认后）

1. **详情交互试点**：按INTERACTION.md先制作可点击的列表—详情—看图—收藏—预约原型，沿用现有色调；确认后实现美甲详情和必要入口。新增路由不替换任何原路径，复用现有商品读取/身份/预约工具。
2. **共享组件与主题**：以opt-in样式更新图库、收藏、联系区；核验新旧页面并存。再完成全局导航/系统主题所需的兼容映射，按批准范围扩展。
3. **第一轮视觉验收**：编译并打开微信工具；对详情默认/加载/错误/空态、不同尺寸和主题截图；录制短视频检查按压、转场、收藏、滚动和弹层，静态截图不作为动效验收证据。
4. **第二轮视觉验收**：对修正后的版本重新截图，检查实际照片裁切、字体/触摸/安全区、长内容、低性能与减少动态场景。
5. **行为回归**：详情直达与返回列表位置、分类切换、全图预览返回详情、收藏/取消、登录取消、手机号后恢复选款、无款预约、已满/冲突时段和申请回执。运行现有75项测试及受影响新增检查；会员只读/缓存行为不能退化。
6. **交付与扩展**：给出改动文件、两轮截图、自动化与真机结果及剩余项。后续顺序建议饰品/鲜花→收藏→我的/会员卡→预约→记录/资料。上传/部署不属于本次方案确认。

真实交互以测试环境/测试账户为优先；视觉检查不默认创建门店预约、不拨打电话、不发留言、不执行资金操作。保留支付/API/后台边界。

## 商品页面减法（2026-10-19，用户最新要求）

以实物照片、商品名、价格和主操作构成层级，保留原品牌色。删除常驻的验收说明、实现说明、预约前须知与重复的确认提示；必要的登录、加载失败等反馈仅在对应操作或异常发生时呈现。
