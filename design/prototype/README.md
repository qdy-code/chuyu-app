# 月光石屿商品详情交互原型

用户于2026-10-15确认制作可点击原型。本目录是独立浏览器原型，不是已接入微信的小程序页面；不会调用登录、会员、预约或资金接口。

## 打开

在仓库根目录运行：

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory design/prototype
```

访问 <http://127.0.0.1:8768/>，也可以直接打开 `index.html`（本机浏览器允许本地会话存储时可体验收藏）。服务器仅监听本机，不是公开部署。

详情可直接进入 <http://127.0.0.1:8768/#detail/moon>。

## 可体验内容

- 列表分类、快捷预约、明确的详情入口；返回列表恢复原滚动位置。
- 商品详情、完整描述、参考价、固定底部操作、到店说明与联系入口。
- 横向滑动与按钮翻图、大图预览、返回时保留图序。
- 收藏/取消，成功后更新状态；模拟保存失败时不改变原状态。
- 预约面板、演示日期/时段、备注、确认和明确标注的演示回执。
- 浅深色、320/375/390/430px预览宽度、减少动态模式、加载/错误/缺图/缺价/下架/长内容。
- 模态背景不可交互，Escape关闭、Tab焦点约束、关闭后恢复焦点。

原型收藏只写 `sessionStorage` 的专用演示key，不读取或修改小程序登录/收藏。刷新会话内保留演示收藏；关闭浏览器会话或重置后清除。

## 数据与图片

本轮对公开商品接口做了一次无认证只读查询，`NAIL` 返回空数组。未下载或使用会员/预约数据。

`assets/swatch-*.svg` 是本地绘制的指甲构图示意，均标注“构图样片 · 非实拍”，不是门店作品。第一件商品名称与168元价格取自仓库已有开发演示条目，另外两件用于滚动与缺价体验；所有内容均不代表实时上架状态。预约时段完全模拟，禁止用作实际排期。

`tokens.css` 从 `../tokens.json` 的语义色导出，沿用旧版奶油白、月光灰蓝和深灰主色。深色是兼容提案；系统主题、原生导航、真机性能仍需在小程序接入时验证。

## 两轮检查

第一轮：完成主流程和异常状态检查，发现旧Toast会覆盖后续新打开的预约面板，及程序聚焦的面板容器出现浏览器默认蓝框。修正为页面/弹层导航时清除旧提示、仅取消面板容器默认轮廓，交互控件仍保留可见焦点。

第一轮“详情直达”检查失败的用例原先在同一文档相同hash下重复导航，不能准确代表首次直达。第二轮改为先离开文档再从完整详情地址进入，并补充对外部hash导航的处理。

第二轮：`verification.json` 记录 **26项通过、0项失败、0个未捕获浏览器异常、0次外部网络请求**。包括真实浏览器触屏事件驱动的横向滑动、返回位置、图序、收藏失败、面板状态、备注保留、减少动态和320px实际浏览器视口无横向溢出。

截图在 `screenshots/`：

- `round-2-detail-overview.png`：整体原型与详情首页。
- `round-2-booking-clean.png`：修正后的预约面板。

这些验证仅覆盖浏览器原型，不能等同于微信两轮视觉/真机验收，也没有验证真实登录、手机号、保存或预约提交。

## 复验

本机服务器运行时，使用Node和Chrome执行：

```sh
node --check design/prototype/prototype.js
node design/prototype/verify.mjs
```

脚本默认使用macOS Chrome路径，可通过 `CHROME_PATH` 指定其他位置；采用隔离浏览器profile，不操作日常浏览器会话。重新运行会更新第二轮截图和 `verification.json`。
