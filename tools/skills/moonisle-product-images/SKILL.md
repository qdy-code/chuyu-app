# 月光石屿商品图

本地管理输入、生成任务、原图与审核记录；调用会话内置 image 模型。不是离线模型，也不是脱离 Codex 的无人值守生图服务。

## 输入与品牌

读取 [brand.json](references/brand.json)；格式及命令见 [workflow.md](references/workflow.md)。配置依据项目 `design/DESIGN.md` 和现有品牌素材；摄影细节是首版建议。用户调整方向时更新配置，不堆叠冲突提示词。

- `product-edit`：有真实商品照片，保留商品本体、颜色、件数、材质特征、结构与比例，只改变用户指定背景/光线。要求 `sku`、`preserve`、`edit_scope` 及至少一张商品图。单角度照片不能推演隐藏的背面/扣头/结构。
- `concept`：从文字生成新款或营销灵感。在清单与交付文字标为「AI 概念图」，不称为门店案例、现货或真实商品。用于宣传时配相应说明；默认图片本身不嵌字。
- 用户需要两者时支持两种模式，但没有实物图的条目仅制作概念图，不能用概念图填补商品事实。
- 每张输入图区分商品原图（身份依据）与风格参考（只借摄影语言）。不把参考图的款式当成用户商品，不编造材质、花材数量、价格和库存。

## 执行

1. 写入批次 JSON，用 `scripts/workflow.py prepare` 生成每张图独立的 prompt、tool-request 和 manifest。重入时读已有 manifest，跳过成功归档项，避免重复消耗。
2. 用 `view_image` 逐张观察本地参考图，核对提示词中图片角色和顺序。缺失参考文件时报告该条目问题，继续独立条目，不擅自更换模式。
3. 使用内置 `image_gen`，每张图一个调用，参数取自 `tool-request.json`。准备好的请求不是执行证据。无参考图的新生成省略 reference 参数；本地参考用 `referenced_image_paths`；未落盘的会话图片按工具规则用最小 `num_last_images_to_include`，不要混用两种参数。
4. 默认无需 API key。仅在用户明确选择 CLI/API 时读取系统 imagegen skill 并用其随附 CLI；不能因批量或失败偷偷切换 API/模型。工具不可用时保留任务并说明未生图。
5. 用实际返回的本地文件，或从实际返回的 data URL 保存文件，不猜测路径。`capture` 复制原图到批次目录，不覆盖历史输出；归档后审核仍为 pending。
6. 逐张看图并填写 `review.json`：品牌构图、主体细节、瑕疵、参考保真（概念图不适用）、裁切可用性。实物图必须与原图对照，脚本不能自动判合格，模型不能保证像素级保真。
7. 明显瑕疵可做一次针对性修改，保存新 job id（如 `nail-01-r2`），明确只改哪个问题并重申保留项。第二次仍失败则交付候选和问题，不无限重试。用户指定数量/预算优先。
8. 本地保存图片、提示词、manifest 与审核结论，展示选中图并报告绝对路径。概念图通过不等于真实可售，实物优化图仍待经营者确认。不自动上架、改数据库或替换线上素材。

## 视觉检查

- 美甲：手指与甲片连接自然，甲形、色块、钻饰数量和位置不漂移；保留皮肤纹理。无真人需求时优先甲片，降低手部生成误差。
- 饰品：扣头、连接、左右配对、串珠数量、石纹和镶嵌合理；不将天然石升级为无瑕宝石，不凭图宣称天然/纯银。
- 鲜花：花种、枝数、开放程度、包装与束型符合输入，花头与茎连接自然；实物不能凭空增加花量或换花材。
- 小程序详情目前近方形 aspectFit，列表横向 aspectFill；方图不等于自动适配。检查完整方图及列表裁切；没有实测页面时只报告图片级预检。
