# 生产数据安全与恢复

## 数据保护原则

- 会员、余额、积分、预约、充值和消费记录仅保存在生产 PostgreSQL，不得写入 Git 仓库。
- 上传图片使用独立 Docker 数据卷，数据库和图片卷名称固定，不随项目目录变更。
- 每次更新前先备份，更新后再生成一份基线备份。
- 生产只执行 `prisma migrate deploy`，禁止执行 `prisma migrate reset`、`prisma db push --force-reset` 或生产 seed。
- 日常备份保存在 `/var/backups/moonisle`，不放在 Git 工作区内。

## 备份策略

1. 每天 02:30 导出 PostgreSQL 自定义格式备份和上传图片压缩包。
2. 备份完成后立即检查数据库目录、压缩包和 SHA-256 校验和。
3. 服务器保留 30 天应用级备份。
4. 阿里云文件备份同步 `/var/backups/moonisle`，并启用系统盘自动快照。
5. 每月做一次独立测试库恢复演练，记录时间和结果。

## 常用命令

```bash
# 手动生成备份
sudo bash /opt/chuyu-app/deploy/backup.sh

# 校验最新备份
sudo bash /opt/chuyu-app/deploy/verify-backup.sh

# 查看备份日志
sudo tail -n 100 /var/log/moonisle-backup.log
```

## 恢复约束

正式恢复前必须先停止 API 写入，再对当前数据库生成额外备份。先在独立测试库还原并核对会员数、余额合计、积分合计、预约数和消费记录数，确认无误后才能替换生产数据。
