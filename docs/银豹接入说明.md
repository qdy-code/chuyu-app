# 银豹会员与账务接入

## 已确认的第一阶段

微信支付商户尚未开通。本阶段由银豹完成开户、充值、消费、退款和积分调整，小程序展示银豹账务；不实现小程序支付或向银豹写入资金。两套系统尚未正式营业，现有数据为测试数据，但部署仍保留数据并执行备份。

代码基于 `codex/production-20260714` 的 `4017efe`，在 `codex/pospal-integration` 分支开发。现有线上地址为 `https://chuy.shop/`，仓库旧上线清单中的“服务器已释放”记录不代表当前状态。

## 使用方式

1. 在银豹收银系统创建会员并填写准确的预留手机号。
2. 顾客在小程序微信登录后，首次使用点击“微信授权手机号”并确认；拒绝授权或接口不可用时可主动选择手动填写。随后可主动选择头像、点选微信昵称，保存到小程序后台，也可跳过。已登录会员可从首页的完善资料入口或账户资料中修改。手机号不会触发自动银豹关联。
3. 管理员进入“银豹连接”，选择小程序会员，查询同手机号的银豹候选会员。
4. 门店核实顾客本人身份，勾选确认后关联指定银豹会员。一个银豹会员只能关联一个小程序会员，关联操作写入审计日志。
5. 顾客打开会员卡或刷新资料，系统按已保存的银豹 UID 查询余额、积分、等级、折扣和会员号；充值、消费记录从银豹读取。

出现重复手机号、手机号不匹配、停用/挂失会员、连接账号变更时不能自动关联。当前不提供自助解绑或跨账户转移，避免错误授予资金账户访问权。未关联顾客显示“待关联”，不展示旧测试余额。

## 账务边界

- 银豹为余额、积分、会员等级和折扣的来源。本地仅保存最近一次成功读取的投影及同步时间，不反向调整银豹。
- 最新会员资料读取失败返回错误，不伪装成零余额或返回本地测试余额。微信登录及普通资料更新使用明确带同步时间的缓存，不依赖银豹服务即时可用。
- 启用银豹来源后，原本地充值、扣款、积分/余额修改、订单冲销被服务端拒绝；管理后台隐藏旧充值、消费、等级和营收入口，保留会员资料、预约、产品展示及银豹核对。
- 银豹 `money` 已包含 `giftMoney`，不再次相加。充值记录分开显示充值本金及赠送金额。
- 消费记录包含正常消费及退货/退款，反结账单据不展示。充值和消费各展示最近 100 条，页面说明此范围，不自动多页拉取。
- 当前已核对的文档没有提供会员积分完整变动明细查询能力，积分明细由门店在银豹查询，小程序展示当前积分。
- 国内门店业务时间按北京时间解析后返回 UTC 时间戳；消费业务日期保留银豹原始日期，客户端时间按设备时区显示。

## 配置

微信手机号授权需要已认证的非个人主体、可用的接口额度，以及微信后台“用户隐私保护指引”中声明收集手机号。`getPhoneNumber` 的动态 code 与微信登录 code 分开使用，后端一次兑换后保存手机号；客户端不自动重试一次性授权 code。小程序里的隐私政策也说明获取方式，并保留手填入口。银豹关联仍要求门店人工核实身份。

本地使用 `apps/api/.env`，Docker 使用 `deploy/.env.production`。凭证只保存在服务端，禁止提交到 Git 或前端。

```dotenv
POSPAL_ENABLED=true
POSPAL_ACCOUNT_SOURCE=pospal
POSPAL_APP_ID=<开发应用标识>
POSPAL_APP_KEY=<开发密钥>
POSPAL_ACCOUNT=<目标门店或总部账号>
```

默认 `POSPAL_ENABLED=false`、`POSPAL_ACCOUNT_SOURCE=local`，保留原本地行为。生产选择 `pospal` 时必须同时启用连接并完整配置凭证；非法来源或缺失凭证会阻止启动。本阶段没有银豹资金写入接口。

## 接口与成本

线上反向代理为以下接口加 `/api` 前缀。新管理员接口要求管理员 Bearer Token；会员接口从签名令牌提取本地用户 ID，再查服务端绑定，不能传入其他人的 UID。调用方不能覆盖银豹凭证或目标门店账号。

| 接口 | 行为 | 单次银豹 Token |
| --- | --- | --- |
| `GET /admin/pospal/status` | 配置状态 | 0 |
| `POST /admin/pospal/connection-test` | 读取门店 | 100 |
| `POST /admin/pospal/members/:id/preview` | 按手机号查最多两名候选 | 100；无手机号不调用 |
| `POST /admin/pospal/members/:id/link` | 查询指定会员、核对身份、保存本地绑定 | 120 |
| `GET /members/me`、`GET /admin/members/:id` | 关联后读取余额、积分和等级 | 120 |
| `GET /recharges/my` | 指定会员最近 100 条充值记录 | 100 |
| `GET /consumptions/my` | 指定会员最近 100 条销售/退货记录及商品名称 | 120 |

管理员会员列表只读取本地投影，登录不主动请求银豹；没有绑定时不请求银豹记录。所有远程请求固定官方 HTTPS 域名、禁止重定向、8 秒超时，不自动重试、翻页或轮询。控制台调用记录可核对实际消费。

## 部署与回退

新增 migration 仅创建 `PospalMemberLink` 及唯一约束、会员外键，不删除或重置现有业务数据。更新前、后分别执行项目备份脚本并验证格式。现有服务器原目录没有 Git 元数据，使用独立 Git 部署目录准备版本，保留原目录；Docker 沿用原项目名和固定数据库、图片、证书卷。

迁移通过独立的临时容器运行，与 API 使用同一镜像，但只连接数据库网络，不占用 API 的固定代理 IP；更新运行中的服务时也能执行迁移。

部署记录应另外保存实际提交、镜像 ID、环境配置备份、备份文件和外部验证结果。回退先恢复前一镜像及环境配置；新增绑定表不需要删除。本阶段不执行生产 seed、数据库 reset 或清理旧测试记录。

## 验证

```sh
pnpm --filter @member-platform/api build
pnpm --filter @member-platform/api test
pnpm --filter @member-platform/api test:e2e
pnpm --filter @member-platform/admin-web build:release
pnpm --filter @member-platform/member-miniapp build:release
```

数据库测试必须使用名称包含 `test` 或 `e2e` 的独立数据库，不能指向业务库。新增 PostgreSQL E2E 覆盖重复绑定幂等、身份审批、读取银豹变化、禁用本地充值、跨会员隔离和上游失败；银豹响应在这些测试中模拟，不代表真实客户已经完成关联或真实 POS 充值验收。

正式小程序产物需由开发者工具上传体验版，并在真实手机上完成验证；本阶段不自动发布小程序。微信支付、线上积分兑换或写入银豹的跨系统交易另行开发。

小程序正式构建和产物检查均以 `apps/member-miniapp/release-target.json` 中确认的 AppID、API 地址为准。当前为 `https://chuy.shop/api`；旧域名 `moonisle.shop` 不可用于本次部署。变更线上域名时须同时核对服务器、微信合法域名及此文件，避免配置和产物同时保留旧地址而通过检查。
